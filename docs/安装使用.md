# 在 Mac 上安装与使用听译

听译在 macOS 14 或更新版本运行。优先下载 GitHub Releases 中的最新版安装包；需要自行开发时再下载源码和配置 Xcode。

## 直接安装

打开 [最新版下载](https://github.com/xiuleiyy/hearnote-mac/releases/latest)，在 Assets 下载 `HearNote-Mac-arm64.dmg`。仓库为 public，同事使用浏览器下载 Release 无需 GitHub 账号或仓库访问权限。

固定的 [最新版 DMG 下载入口](https://github.com/xiuleiyy/hearnote-mac/releases/latest/download/HearNote-Mac-arm64.dmg) 随 Latest 更新。需要 App ZIP 时下载同一 Release 的 `HearNote-Mac-arm64.app.zip`；`SHA256SUMS` 和 `Installation.md` 分别提供校验值与安装步骤。

每次 `main` 更新通过 Mac 构建、测试和安装包检查后，会自动发布到 Releases。安装包上传后重新下载核对字节与 SHA-256，再发布并更新 Latest；新版本确认成功后才清理较旧版本，保留最近三个由自动流程发布的 Release。Git tag 不删除。失败或已过期构建不替换最新版、不触发旧版清理。

开发者需要源码 ZIP、真实日志或修复 diff 时，在 Actions → “Mac 安装包”的成功运行中下载 Artifacts 里的 `HearNote-Mac-arm64`；这些文件不随 Release 安装包发布。

解压交付文件后，打开其中的 `.dmg`，把“听译”拖到 Applications，再从 Finder 启动。也可解压 `.app.zip` 后复制 App。安装和日常使用不需要 Xcode；当前 arm64 安装包面向 Apple Silicon Mac。

从旧版升级时，先保存会议并退出旧 App，从 Applications 启动新版 `听译.app`，再更新 Dock 快捷方式。新版沿用原有笔记目录与 Keychain 标识，无需删除笔记、模型缓存或重新填写 Key。源码仓库、可执行文件和交付归档保留 HearNote 名称。

当前为 ad-hoc 签名，没有 Developer ID 签名或公证。macOS 如拦截，使用系统提供的“打开”或“隐私与安全性”入口授权，不关闭系统整体保护。核对随包的 SHA256SUMS、源码提交和结果说明；CI 安装包仍需按本机验收指南测试音频、翻译等功能。

## 取得源码

仓库 `xiuleiyy/hearnote-mac` 为 public，在开发环境直接运行：

```bash
git clone https://github.com/xiuleiyy/hearnote-mac.git
cd hearnote-mac
```

如已安装 GitHub CLI，也可以用 `gh repo clone xiuleiyy/hearnote-mac`。向仓库推送修改需要 GitHub 登录与写权限；App 中的模型认证使用 Bedrock API Key。

已有副本时，先确认没有未保存修改，再运行 `git pull --ff-only` 取得更新，不要直接覆盖工作目录。

## 构建与安装

需要 Swift 5.10+ 和完整 Xcode。新的 Apple 本地识别分支需 Xcode 26+、Swift 6.2+ 和 macOS 26 SDK。仅 Command Line Tools 不够；请安装并打开 Xcode 完成许可证及组件初始化，在 Xcode → Settings → Locations 选定编译工具。用 `swift --version` 检查版本，工具版本不足时先升级。

在源码根目录运行：

```bash
bash scripts/build-mac.sh --open
```

也可双击根目录的 `开始使用.command`。首次构建会下载固定版本 WhisperKit `1.1.1` 及其依赖。

脚本依次执行核心测试、release 编译、复制依赖资源、将内置 PNG 转成 Mac 图标、生成 `dist/听译.app` 并进行本机 ad-hoc 签名。图标无需额外下载或配置。编译或测试失败时先解决报错，不能把源码解析通过视为安装成功。

成功后可将 `dist/听译.app` 复制到 `/Applications`，通过 Finder 打开。当前构建没有 Developer ID 签名或公证；如果 macOS 拦截，使用系统提供的“打开”或“隐私与安全性”入口授权，不关闭系统整体保护。

## 首次配置

1. 在 App 首次配置页填写自己的 Bedrock API Key。Key 保存在 macOS Keychain，Region／模型可调整；完整预置 ID 见 README。

2. 点击“测试连接”。这是一次真实模型调用，可产生模型费用；成功后保存。HTTP 429 表示服务限流，应稍后重试或选择可用模型，不把报错耗时当翻译速度。

3. 识别默认本地 Whisper。全英文会议选 English，中英交替或混用选“中英混合”；可提前点击“准备模型”，首次下载与预热完成后复用缓存。开始会议不会等待模型：先录音，后台准备完成后转写新声音；准备期间的音频可在会后重新转写。下载失败可导入包含权重与 tokenizer 的完整本地目录。

4. 按需允许麦克风和系统录制权限。默认 Whisper 无需 Siri／听写。单语选择 [Apple 本地识别](Apple本地识别.md) 时，macOS 26 的新路径也无需开启 Siri／听写，首次可能准备系统语言资源；旧系统仍需相应语音识别权限与可用服务，联网选项由用户明确开启。

可以跳过 Bedrock 配置先使用录音和转写。文字翻译与摘要需要可用 Key 和网络，本地 Whisper 识别完成准备后在 Mac 内执行。

## 会议记录

选择麦克风、系统声音或同时录制；系统声音包含 Zoom、飞书等会议软件播放的音频。建议戴耳机，减少麦克风重复收录会议声音。

点击“开始会议录音”或 `⌘⇧R` 后，在主窗口选择来源和语言并开始。会议不再弹出固定大小的独立窗口；拖动主窗口标题栏移动，拖动边缘缩放，字幕随可用空间换行。

会议语言默认 English，实时翻译默认目标“简体中文”。已有版本首次升级也采用这两个默认，之后会保存你手动改选的语言；独立翻译页的语言设置单独维护。

中英会议选择“中英混合”和“中英双向”。中文译英文，英文译中文；同句混用按主要语言处理，均衡混合可显示完整中英两行。专有词和 `原词=译法` 术语表可在设置中维护。

English 固定英文识别，适合全英文会议；中英混合在中文／英文间选择语言。字幕出现错误语种时，结束保存后选正确语言与本地 Whisper，点击“重新转写”；旧错误字幕不会因设置改变自动修正。

新识别输出会移除 Whisper 的 `[BLANK_AUDIO]` 技术占位，保留正常文字和时间戳。旧笔记不会自动改写；如果原转写已含占位，先保留所需校对内容，再重新转写。

会议界面分别显示麦克风／系统声音是否收到音频、识别状态与持续错误。能回放声音但没有文字时，应检查识别状态；“已收到音频”只代表数据已采集，不保证其中有可识别的人声。取消模型准备不停止录音。

录音开始后，字幕占据主区域；语言、实时翻译开关和收音摘要移到下方。“详情”默认收起，展开后显示完整准备／识别信息，可拖动字幕下方分隔线调整详情高度。结束保存按钮固定在底部。准备进度、取消准备入口和异常摘要在详情收起时也可见。

“实时翻译”可在开始前和录音中开关。关闭时录音与转写继续，取消在途翻译；重新开启处理新产生的稳定文字，关闭期间的文字可在会后用“翻译全文”处理。

会议收音时，每段原文在上、金色译文在下，时间戳和声音来源共用。所有片段在同一个列表上下滚动；尚未完成时显示等待／翻译中状态，译文晚到仍放回对应片段。

本地 Whisper 原文会在当前句中持续增补，按句末标点、明显词间停顿或长句上限分段；不会每 3 秒强制换一行。未完句显示“正在补全当前句…”，形成句段后再翻译，减少半句独立翻译。连续没有标点的长发言仍需适度分段，保持译文持续更新。会议状态显示实际加载的 Large v3 Turbo 或 Small；默认值不代表旧配置选择。

这项组句用于新的本地 Whisper 转写。已有笔记不会自动重排或重写；需要时先保存校对内容，再主动对录音“重新转写”。macOS 26 的 Apple 路径按系统结果的音频时间范围持续修订原文和定稿；旧系统保留原分段与稳定策略。

“返回笔记”或切换页面可离开会议页，录音、识别和翻译继续。侧栏“返回当前会议”或 `⌘⇧R` 回到同一场会议，不新建另一场录音。点击“结束并保存”才结束当前会议，随后进入保存的笔记。

点击主窗口左上角红色 ❌ 会缩小到 Dock，App、录音与翻译继续运行；点击 Dock 中的听译恢复窗口。`⌘W` 关闭窗口也不会退出 App，再点 Dock 可重新打开主窗口。需要真正退出时，使用“听译 → 退出听译”或 `⌘Q`，程序沿用结束并保存当前录音的流程。

“跟随最新”开启时，原文更新、译文完成和新段落出现都会滚到最新内容。回看前关闭跟随，录音、识别和翻译继续；点击“回到最新”恢复跟随。中英双向沿用当前设置。

结束保存后进入“对照”页，已完成的逐段译文随笔记保存在本机，重开仍可对照；未完成的段落标记“未翻译”。修改原文会清除该段的旧译文。旧版笔记只有整篇译文时，仍可到“翻译”页阅读；“翻译全文”生成整篇译文，不会按时间戳猜测逐段对应。

笔记的“翻译”页优先显示已保存的全文译文；还没有全文时，会显示已完成的有效逐段译文及完成数量。没有生成过译文时，页面说明当前状态，不用空白页代替已有实时结果。

“翻译全文”“生成摘要”“重新转写”在会议开始、录音、保存或其他处理期间暂不可用，页面会显示原因及返回会议／取消任务等可用入口。先结束并保存会议，或等当前任务完成，再处理全文；录音中需翻译时到当前会议开启“实时翻译”。只读原文保持正常对比度，可选择复制，保存后空闲时可校对。

结束后保存，可点时间戳回听、校对原文、生成摘要，以及导出 TXT、SRT、Markdown 或 JSON。原文校对会清除过期翻译和摘要，需要重新生成。

### 外放与自己的发言

耳机不是启动麦克风录音的必要条件。只录自己的声音选“麦克风”，同时录自己和会议软件声音选“麦克风 + 系统声音”；“系统声音”不采集麦克风输入。

双源录音使用本地 SpeexDSP，以系统声音作参考，尝试消除麦克风收回的扬声器声；处理后的麦克风供实时识别和最终录音使用。底部显示实际处理、参考覆盖与原音透传状态，参考尚未就绪或音频异常时保留麦克风原音，可能再次出现重复。“正在处理”不代表回声已消失。不会根据系统有声音就关闭麦克风。外放音量过高、失真和设备延迟仍会影响效果，实际外放与同时讲话需要复测；耳机可进一步减少串音。详细步骤见 [外放回声消除](外放回声消除.md)。

结束保存后，另保留处理前的麦克风、系统声音与处理后的麦克风音轨。若最终回放听不到自己，可先回听原始麦克风：原音有自己的声音而处理后没有，属于处理问题；原音也没有则需检查采集。备份只保护已采集的声音，不能补出未录到的声音。

如果选择了“麦克风”，保存后的回放仍听不到自己的声音，先核对 macOS「系统设置 → 声音 → 输入」的所选设备、输入音量与说话时的输入电平，再核对听译的麦克风权限。听译使用系统提供的输入通道；会议软件单独选择的麦克风不代表听译也使用同一设备。

结束并保存当前会议后，可新开一段 10 秒测试：暂停外放，关闭实时翻译，只选“麦克风”并说话；记录系统输入电平、App 的麦克风状态和保存后的回放结果。先区分没有采集到自己的声音与采集到了但没有文字，再检查识别语言；English 固定英文，自己讲中文且对方讲英文时应选“中英混合”。

## 独立翻译

侧栏选择“翻译”或按 `⌘⇧T`：

- 文字：输入后点击“翻译”或按 `⌘Return`；可选择语种、交换语言、复制或朗读译文。

- 语音：点击麦克风，先显示识别原文；说完结束，再翻译这一轮。会议录音和翻译语音共享麦克风／识别模型，不能同时使用。

- 对话：双方轮流点击中文／英文语音按钮，逐轮显示原文与译文。

- 图片：导入图片或截图，先本地 OCR；校对文字后点击翻译。

- 历史与收藏：成功译文保存在本机，支持恢复和收藏。历史保存异常时留意 App 的未保存提示。

录音、笔记、模型和翻译历史位于 `~/Library/Application Support/HearNote/`。API Key 只保存在 Keychain；翻译与摘要向所选 Bedrock endpoint 发送对应文字，原始录音不发送给 Bedrock。

已结束并保存的录音在 `~/Library/Application Support/HearNote/media/`，会议录音文件为 `.m4a`，文件名采用 UUID。笔记的“导出 → 在 Finder 中显示录音”可定位当前文件。

本版起，成功保存的新会议原音另存于 `~/Library/Application Support/HearNote/Recording/Originals/<会话 UUID>/`。可从录音笔记的“导出 → 打开原始音轨总目录”进入，再按文件夹录制时间查找；该入口是所有会议原音的总目录，不直接对应当前笔记。原始麦克风为 `microphone-original.caf`，系统声音为 `system.caf`，双源处理轨为 `microphone-cleaned.caf`；只有实际存在的来源才有对应文件。`diagnostics.json` 记录录制时间、音轨格式和处理统计，不包含识别文字或密钥。

原始 CAF 备份只保存在本机，会额外占用磁盘空间。需清理时先核对最终录音和所需原音已备份，再由自己删除对应原音文件夹；App 不自动清理这些备份。旧版成功保存后已经删除的原音无法恢复。

正在录制或保存／归档失败时，原始音频仍在同级 `Recording/` 目录中以 `.meeting-` 开头的隐藏目录。Finder 按 `⌘⇧G` 可直接输入上述目录或错误提示中的具体路径；数据目录保留 HearNote 名称。

## 验收与打包

先按 [Mac 本机验收](Mac本机验收.md) 核对编译、权限、音频、翻译质量和实际速度。通过后运行：

```bash
bash scripts/package-mac.sh
```

脚本使用已构建的 App 生成并验证 `dist/听译.dmg`，不重复编译或测试。打开 DMG，将 App 拖到 Applications；从安装后的 App 再启动一次确认可用。

## 交给本机 Claude／Codex 验收

当前分工是由开发环境修复源码、macOS CI 构建安装包，北京 Mac 主要负责安装与实机验收。可直接给本机代理：

> 请读取本轮安装包交付说明、README.md 和 docs/Mac本机验收.md，下载并校验成功 CI 的 arm64 App／DMG，在这台 Mac 安装并运行。按文档测试麦克风、会议系统音、中英混合转写和双向翻译，核对数字与否定词、记录本机速度。发现程序问题时记录复现步骤、实际结果和无凭据证据，回传开发环境统一修复；本轮不自行修改程序逻辑或推送源码。不要导出 API Key；未测项目明确标为未测，返回 App／DMG 的本机绝对路径。

开发环境的后续源码修改均按 [AGENTS.md](../AGENTS.md) 同步到 GitHub，并取回成功 CI 安装包。同步失败应明确报告，不能把仅本地提交说成已同步。
