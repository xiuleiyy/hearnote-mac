# 外放时同时录制会议与自己的讲话

选择“麦克风 + 系统声音”。系统音保留为“会议声音”，同时作为回声参考；
麦克风经本地 SpeexDSP 自适应回声处理后，作为“麦克风”送入实时识别和保存录音。
不需要额外 API Key，不上传音频，不使用模型修写原文来隐藏重复。

仅选“系统声音”时不收自己的麦克风；仅选“麦克风”时没有系统参考，不进行这项双源回声处理。

## 状态与边界

- “回声处理中”：该帧确实经过本地回声滤波，显示本场的参考覆盖、处理和原音透传比例；开头提示正在适应声音。参考覆盖不等于处理比例，两者都不证明回声已消失。

- “系统参考暂未就绪，麦克风原音透传”：对应时间的参考暂时缺失；优先保留自己的讲话，因此可能再次出现重复。每个麦克风采集包从实际到达处理器开始，最多等待 180 ms，包内的帧共享截止时间；不会因采集时间戳已旧而直接放弃等待，也不会逐帧重复等待导致积压。

- “音频数据异常，麦克风原音透传”：该帧的格式、幅度或参考数据不满足处理条件，没有把原音透传误报成成功处理。

- 处理不可用：显示原因，并保留原始麦克风轨用于恢复或保存；结束时等待处理尾帧与实时输出，不直接丢弃尾音。

状态中的麦克风电平衰减是单帧输入／输出总 RMS 的变化，包含自己的讲话、背景声与回声。它不是 ERLE 或准确率，不能把电平降低当成外放回声或双讲验收通过。

系统与麦克风采样率统一为 16 kHz 单声道，每帧 20 ms，使用共同主机时钟对齐；
系统原始录音轨保持原格式。声学滤波器覆盖约 250 ms 的回声路径，不使用按音量关闭麦克风的规则。

音量过高造成扬声器或麦克风失真、较长设备延迟、设备切换、复杂立体声和参考中断，都会影响效果。
滤波器需要适应当前声学环境；开头或环境变化后仍可能有残留。
耳机可进一步减少串音，但不是麦克风录音的前提。不能承诺所有设备下零回声、零双讲损伤。

## 原始音轨与声音恢复

本版起，成功保存的新会议会将原始音轨归档到：

```text
~/Library/Application Support/HearNote/Recording/Originals/<会话 UUID>/
```

- `microphone-original.caf`：回声处理前实际采集的麦克风。

- `system.caf`：实际采集的系统声音。

- `microphone-cleaned.caf`：双源录音时回声处理后的麦克风，参考缺失的部分仍是透传原音。

- `diagnostics.json`：录制时间、各轨时长／格式／起始偏移，以及回声处理的数值统计；不含识别文字、密钥或音频内容。

只有实际存在的音轨才有对应文件。笔记“导出 → 在 Finder 中显示录音”定位最终 M4A；“打开原始音轨总目录”进入所有会话的原音目录，按文件夹修改时间或诊断中的录制时间找到本场。总目录入口不假定当前笔记与最新文件夹对应。

这些未压缩 CAF 只保存在本机，会额外占用磁盘空间，App 不自动清理。确认最终录音和必要原音已备份后，可以自行删除不需要的会话文件夹。

若原音归档失败，保留 `Recording/.meeting-<会话 UUID>/` 并显示位置；不因为最终混音已成功就删除原音。旧版成功保存后已经删除的原音无法补回。

自己的声音在原始麦克风中也不存在，应继续检查输入采集；原音存在但处理轨没有，检查回声处理；处理轨存在但最终录音没有，检查混音与轨道偏移。原音保全只能恢复已采集的声音，不能修补没有录到的讲话。

## 本机复测

先在“系统设置 → 声音 → 输入”确认输入设备和音量，对该设备讲话时输入电平应变化。
听译使用系统输入通道，Zoom／飞书单独选择的麦克风可能与它不同。
关闭实时翻译可先隔离音频与识别问题；自己的发言有中文时请选择普通话或中英混合。

1. 暂停外放，只选“麦克风”，录制 10 秒自己的声音，保存回放。回放没有自己的声音先记为输入采集问题；有声音但没文字记为识别问题。

2. 使用相同输入设备与测试材料，先戴耳机录双源，确认两端声音正常；再改用内置扬声器。记录实际输入／输出设备，不能将耳机改变输入设备的结果直接算成只改变回声路径。

3. 选择双源，播放约 30 秒自己有权测试的语音，保持自己不说话。分别观察开头 3 秒和之后，同一句远端语音是否仍出现两条、保存回放是否有明显重影。

4. 另开一场，从录音第一秒就同时讲话；随后与远端交替至少 1 分钟，并在对方讲话时轻声插话约 15 秒。自己的话应有麦克风字幕和回放，远端仍有会议声音字幕。不能先预热数秒才测双讲；记录失字、压音或残留重复。

5. 暂停播放 20 秒，对麦克风讲话，再恢复外放。参考缺失时自己的讲话必须保留，恢复后状态继续更新。

6. 在一句话尾部立即结束并保存；分别回听本场原始麦克风、处理后的麦克风和最终 M4A，检查自己的讲话与最后一个词在哪一步缺失。重开 App 后原音仍应存在；再开始下一场，上一场的回调或字幕不得出现。

对每项记录：系统输入／输出设备、外放音量、会议语言、处理状态、重复字幕次数、保存回放与自己的讲话是否清楚。
仅提交经过确认可分享的测试结果，不包含 API Key 或未经授权的会议内容。

## 开发检查

Core 的合成 DSP 测试验证延迟回声衰减、弱本地声音、从第一帧开始双方同时讲话、无参考透传、滤波器重置与输入边界。对本地声音投影保留的断言不代表远端回声已被抑制到不能被识别。
Mac 的 `scripts/check-mac-echo.sh` 使用实际处理器与合成 PCM 检查格式转换、时间戳、晚到参考的到达截止时间、保存轨、原音归档失败保护及停止排空。
到达截止时间检查使用可控单调时钟，并等待音频串行队列与已提交的字幕回调，分别验证等待期间无输出、同包共享截止时间和停止后的完整尾音。生产仍使用系统单调时钟；测试的逻辑时间不能当成实机延迟测量，也不把名义休眠时间当成实际回调时间。
这些检查不需要麦克风权限、客户音频或收费模型，不等于真实外放验收。

依赖来源、固定提交和源文件 SHA-256 见 `Sources/CSpeexDSP/upstream.json`；
源码许可保留在该目录，App 中附带 SpeexDSP 与 KISS FFT 完整许可。
